## Notes

- Only schema validity is measured. Values are not checked for correctness, so the calculation tasks do not show whether the arithmetic is right.
- Each task runs once per mode, sequentially, after one warm-up generation. Timings are wall-clock seconds on a possibly busy machine.
- Call order: llama.cpp reuses the KV-cache prefix of the previous call, so a raw call followed by the strict call of the same task would hand the strict call the prompt evaluation for free. The two runs of a task are staggered (raw 0, raw 1, strict 0, raw 2, strict 1, ...) so consecutive calls never share a prompt, and the grammar cache is emptied before every strict run, so each run pays for its own grammar compile.
- A constrained and an unconstrained generation can differ in length, which moves the total-time comparison in either direction (a negative overhead is possible). The per-character column and the output lengths are there to judge that; the targets are checked against the total-time figures.
- Both modes get the same prompt (task text plus the schema) wrapped in the model's `prompt_template` when one is configured.
